# 트래버스 조향: 토크 한계 근처 튐·풀림 → FrogPilot과 로직 동일화 (2026-11-14)

## 증상 (사용자 제보)

- 11/11 수정 뒤 전보다 훨씬 나아졌다.
- 그래도 조향 토크가 실제 한계에 가까워지면 토크 그래프가 튀고, 조향을 풀었다 잡았다 한다.
- 같은 차에서 FrogPilot은 그러지 않았다. 파라미터는 빼고, 조향 로직이 다르면 FrogPilot과 똑같이 맞춰 달라고 했다.

## 로그로 본 것 (11/13 주행 10개 qlog 스캔 + rlog 6구간)

- 요청 토크가 0.9 이상인 구간에서 운전자 개입(steeringPressed)이 잡힌 프레임은 모두, 측정된 운전자 토크가 요청과 반대 방향이었다.
  - 큰 조향 토크로 핸들 축이 비틀려 반대 방향 토크로 읽히는 것으로 보인다.
- 요청이 0.6 이상인데 CAN 출력이 요청보다 깎인 프레임은 대략 절반이 운전자 토크 제한(`apply_driver_steer_torque_limits`) 때문이었다. 반대 토크가 약 1.4 Nm면 허용치가 0이 된다. 나머지 절반은 변화 속도 제한(+10/−15) 때문이었다.
  - 이것이 '풀었다 잡았다'의 직접 경로다.
  - 이 제한 함수와 상수(65/4/100, 상한 300, 3/10/15)는 FrogPilot과 글자까지 같다.
  - 따라서 차이는 제어기가 한계까지 얼마나 세게, 얼마나 자주 미느냐에 있다.
- 21 km/h 급커브에서 요청이 1.0에 붙었다가 풀리며 0.8↔0.4로 출렁였다. 45 km/h에서 목표가 급변하자 요청이 0.3초 안에 −0.1에서 +0.9로 튀었다.

- 적용 범위: NNFF가 켜진 트래버스·트레일블레이저·트레일블레이저 CC·트랙스(`NNFF_FROGPILOT_PARITY_CARS`, 11/11 동등 처리 대상)만 해당한다. 다른 차는 그대로다.
- 그대로 둔 것(사용자 요청: 파라미터 제외)
  - Kp 1.4 / Ki 0.3 / Kf 1.2: FrogPilot NNFF 기본은 1.0 / 0.3 / 1.0. 한계로 미는 힘에 직접 영향이 있다.
  - 모델 쪽 `LatSmoothSec` 20(0.2초 + 불확실도 비례 추가 평활), `SteerActuatorDelay` 30(0.30초): FrogPilot은 평활 0, 학습 지연.
  - 차체 제원: carrot 무게 2090 kg, 무게중심 0.7, 타이어 강성 기본 1.0 / FrogPilot 1955 kg, 0.4, 0.444.
- 지금 설정에서 꺼져 있어 손대지 않은 것
  - 차선 기반 목표(UseLaneLineSpeed 200)
  - 횡 제어 일시 중지(LatSuspendAngleDeg 300°)
  - custom 조향 상한·변화량(300/10/15로 FrogPilot과 같음)
- 별도 문제로 남긴 것
  - 판다 GM 조향 검사 실패가 송신 거부로 이어지지 않는 점(`//tx = false`)
  - 판다 rate 20/25
  - 학습 지연(lagd) 전처리 차이
  - 모델 출력 사용 방식(action head)

## 개방 루프 재생 (11/13 rlog 6구간, 콤마에서)

- 방법
  - 기록된 차 상태·모델 출력·학습 지연·자세를 그대로 넣어 요청 토크를 다시 계산했다.
  - 송신 토크는 같은 운전자 토크 제한과 변화 속도 제한으로 다시 만들었다.
  - 차 상태는 실제 주행 그대로라, 폐루프 결과 예측이 아니라 같은 상태에서 요청이 어떻게 달라지는지를 보는 비교다.
- 변경을 하나씩 켠 결과
  - 적분(D01)·지연(D03)·경사(D04)·상한(D16): 이 구간들에서 요청·포화·출렁임이 거의 같았다.
    - 상한: 목표가 3.0 m/s²를 넘은 순간이 없었다.
  - 평활 제거(D13): 요청 급변(10 ms에 0.1 넘게)이 2~5배, 출렁임 지표(초당 |Δ요청| 합)가 40~60% 늘었다.
    - 그래서 평활은 유지했다.
- 파라미터 가정(바꾸지 않고 재생만): Kp 1.4/Kf 1.2를 FrogPilot NNFF 기본 1.0/1.0으로 두면 다음과 같았다.
  - 요청이 한계(0.99 이상)에 붙은 시간: 32.9→10.1%, 15.5→10.3%, 15.1→12.8%, 2.3→0%
  - 출렁임: 대부분 구간에서 15~20% 감소. 한 구간은 0.77→0.83으로 조금 늘었다.

- 남아 있던 로직 차이 5가지(D01·D02·D03·D04·D16)는 FrogPilot과 같게 맞췄다.
- 다만 재생으로 보면, 이번 증상의 크기를 바꾸는 것은 로직보다 다음 두 가지였다.

  - 운전자 토크 제한: FrogPilot과 같은 코드인데, 한계 근처에서 핸들 축 비틀림이 반대 토크로 읽혀 걸린다
