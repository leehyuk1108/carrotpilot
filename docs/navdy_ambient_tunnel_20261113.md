# 나브디 앰비언트 어둠 끄기: 터널 예외 (2026-11-13)

## 증상

11/12 20:50 밤 주행 중 터널에서 나브디 앰비언트가 약 28초 꺼졌다(`NavdyAmbientDarkOff=1`).

## 원인

route `0000020c--5789f195f7`을 설치본 `DarkAmbient`로 재생했다.

| 시각 | 입력 | 판정 |
|---|---|---|
| 20:50:25 | 레이더 터널 비트(bus1 `0x460` byte3 bit3) 1, GPS 오차 커지기 시작 | 켜짐 |
| 20:50:30 | 카메라 불빛 판정(bus1 `0x135`) 1→0, 조도 센서 어둠 | 켜짐 |
| 20:50:40 | 불빛 없음 10초 | **꺼짐** |
| 20:50:57 | 카메라 1 복귀 | 꺼짐 |
| 20:51:08 | 불빛 15초 | 다시 켜짐 |

카메라는 대부분의 불 켜진 터널을 도시 불빛(1)으로 보지만, 이 터널은 0으로 봤다(예전 CAN 분석에서도 190--5 터널 일부가 0).

## 수정

- `camera_objects.py`: 같은 bus1 피드에서 레이더 헤더 `0x460`을 받아 터널 비트를 보관한다. 1초 넘게 새 헤더가 없으면 모름(None).
- `ambient_dark.py`: 주행 중 레이더가 터널을 보고하는 동안 카메라의 불빛 없음을 세지 않는다(끄지 않음). 이미 꺼져 있었다면 터널 안에서 2초(`TUNNEL_ON_HOLD_S`) 뒤 원래 조명. 터널을 나오면 불빛 없음 10초를 처음부터 다시 센다. 레이더 값이 없거나 0이면 기존 규칙 그대로.
- `bridge.py`: `CameraObjects.tunnel()` 값을 `DarkAmbient` 입력으로 넘긴다. 새 구독 없음. 조회 시각은 CAN 이벤트와 같은 부팅 시계(CLOCK_BOOTTIME)로, 값을 읽은 뒤에 잡는다(Codex 리뷰: `time.monotonic()`은 절전 뒤 CAN 시각보다 늦어 신선한 값을 버릴 수 있고, 먼저 잡은 시각은 그 사이 들어온 헤더를 미래 값으로 보게 함. 11/13 기준 이 콤마의 두 시계 차이는 0초).
- `docs/user/ko|en/settings.md`: 설정 설명에 터널 예외 추가.

## 검증

- 나브디 테스트(콤마, 설치본 나브디 폴더 사본): 수정본 1621 통과, 기준 1611 통과(새 테스트 10개).
- 20:50 주행 재생(수정본): 레이더 터널 비트가 카메라 0보다 약 5초 먼저 켜져 한 번도 꺼지지 않음.
- 다른 밤 주행 5개(11/10 19:11, 11/11 19:22, 11/12 00:53·20:01 등, 약 3시간)를 수정 전후 판정으로 함께 재생했다(`compare_routes.py`, 기기 읽기 전용).
  - 터널을 지난 이력의 영향을 받지 않는 구간의 꺼짐·켜짐 시각은 수정 전후가 같다. 차이는 터널 안의 동작과, 그 때문에 터널을 나온 뒤 다시 세는 10초 대기에 한정된다. 이 비교만으로 레이더 터널 비트의 오탐이 없다고까지 검증한 것은 아니다(영상·위치 대조는 안 함).
  - 터널 안 차이: 터널 안에서 꺼지던 2건(11/11 19:42:39, 11/12 20:05:04)이 안 꺼지고, 꺼진 채 들어간 터널 2건(11/12 01:01, 11/10 19:50)은 20~33초 일찍 켜진다. 11/11 19:42은 터널을 나온 뒤 어두운 길에서 17초 늦게(나온 뒤 10초) 꺼진다.
